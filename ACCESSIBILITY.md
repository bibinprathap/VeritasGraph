# Accessibility Statement

VeritasGraph is committed to being usable by as many people as possible,
including developers and end users who rely on assistive technologies. This
statement describes our accessibility commitment, the supported environments,
known limitations, and how to report accessibility barriers.

## Our Commitment

We aim to:

- Follow accessibility best practices for documentation and any user-facing
  interfaces.
- Write clear, well-structured documentation with meaningful headings,
  descriptive link text, and alternative text for images.
- Ensure command-line output and logs are readable and not solely dependent on
  color to convey meaning.
- Consider keyboard navigation and screen-reader compatibility for web-based
  components (e.g., the Chainlit UI and any dashboards).

## Supported Environments

- **Documentation**: Standard Markdown rendered by GitHub and common Markdown
  viewers, which are compatible with mainstream screen readers.
- **Command-line interface**: Works with standard terminals and respects
  system color and contrast settings where applicable.
- **Web interfaces**: Modern browsers (latest versions of Chrome, Firefox,
  Edge, and Safari).

## Known Limitations

We are an actively developed open-source project, and some areas may not yet be
fully accessible:

- Some diagrams and architecture images may lack complete text descriptions.
- Web-based UI components may not yet meet all WCAG 2.1 AA success criteria.
- Color contrast in some generated visualizations has not been fully audited.

We are working to address these limitations over time and welcome contributions
that improve accessibility.

## Reporting Accessibility Barriers

If you encounter an accessibility barrier or have suggestions for improvement,
please let us know:

- Open an issue using our
  [issue tracker](https://github.com/bibinprathap/VeritasGraph/issues) and add
  the `accessibility` label.
- Start a conversation in
  [Discussions](https://github.com/bibinprathap/VeritasGraph/discussions).

When reporting, please include:

- A description of the barrier you encountered.
- The page, file, or feature where you experienced it.
- The assistive technology, browser, or environment you were using.

We aim to acknowledge accessibility reports and will work with you to find a
resolution.

## Feedback

Your feedback helps us make VeritasGraph more inclusive. Thank you for helping
us improve.
